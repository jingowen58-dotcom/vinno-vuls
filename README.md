# 一、项目总体定位

## 1.1 项目愿景

VINNO LIFE SCIENCE NETWORK 致力于建设一个以开放数据、标准化数据基础设施、人工智能和全球科研协作为基础的生命健康研究网络。

项目从宠物健康寿命（Pet Healthspan）开始，逐步连接动物医学、遗传学、微生物组学、生物标志物、衰老机制、健康寿命研究以及人类生命健康科学。

全球生命科学领域积累了大量分散的数据和研究成果，包括科研论文、公共数据库、动物医院、检测实验室、高校、研究机构以及长期健康观察项目。

但这些数据往往存在格式不统一、指标定义不同、检测方法不同、数据质量参差不齐、跨机构共享困难等问题。

VINNO 希望通过统一的数据标准、专业研究数据库、数据质量管理体系、AI 科研工具和开放协作机制，让不同来源的数据能够在合规授权的前提下被识别、整理、验证、关联和分析。

我们希望逐步建立一个连接：

- 宠物健康管理
- 动物健康与寿命研究
- 比较生物学与跨物种衰老研究
- 人类健康寿命研究
- 全球科研数据与知识网络

的生命科学基础设施。

## 1.2 核心使命

1. 建立面向生命健康领域的标准化数据基础设施。
2. 建立覆盖宠物、动物和人类健康寿命研究的专业数据体系。
3. 建立统一的数据标准和跨物种数据关联机制。
4. 利用 AI 降低科研信息获取、数据整理和研究分析的门槛。
5. 连接全球科研机构、检测实验室、兽医、研究人员、开发者和用户。
6. 推动科研数据的可追溯、可验证、可复现和合规共享。
7. 通过长期观察和科学研究，探索影响健康寿命的关键因素。

## 1.3 项目定位

VINNO LIFE SCIENCE NETWORK 不是单一的宠物产品品牌，也不是传统检测实验室，更不是一个简单的生命科学信息网站。

它是一个由商业应用、科学研究和开放科研基础设施共同构成的长期项目。

整体包含三个相互连接、但在数据权限和管理上保持独立的体系：

### 1. VINNO HEALTH BUSINESS

生命健康商业应用体系。

主要包括：

- 宠物营养与健康产品。
- 宠物检测服务。
- 宠物数字健康档案。
- AI 健康报告辅助分析。
- 宠物健康管理服务。
- 未来的健康寿命管理产品。

商业体系负责建立用户入口、产品服务、收入和真实应用场景。

### 2. VINNO HEALTHSPAN RESEARCH

生命健康科学研究体系。

主要包括：

- 宠物健康寿命纵向观察。
- 犬猫健康指标与衰老研究。
- 宠物生物标志物研究。
- 动物寿命与衰老机制研究。
- 比较生物学与跨物种研究。
- 人类健康寿命相关公开研究。

研究体系强调科学方法、数据质量、研究伦理、专业人员参与和研究结果的可追溯性。

### 3. VINNO LIFE SCIENCE NETWORK

生命科学数据与开放科研基础设施。

主要包括：

- VULS 统一数据标准。
- 数据处理与质量管理。
- 专业研究数据库。
- AI 科研引擎。
- 科研知识图谱。
- 开放科研协作网络。

三个体系共享基础技术能力，但不意味着商业用户数据可以自动进入科研数据库，也不意味着商业产品的宣传结论可以替代独立科研证据。

# 二、全球生命健康开放科研网络总体架构

## 2.1 六层总体架构

VINNO LIFE SCIENCE NETWORK 采用六层架构：

**L6：OPEN SCIENCE NETWORK — 开放科研协作网络**

**L5：AI RESEARCH ENGINE — 人工智能科研引擎**

**L4：RESEARCH DATABASES — 专业研究数据库**

**L3：DATA PROCESSING & QUALITY — 数据处理与质量管理**

**L2：VULS UNIVERSAL DATA STANDARD — 统一生命科学数据标准**

**L1：DATA SOURCES — 数据来源层**

整体数据流：

数据来源  
↓  
统一数据标准  
↓  
数据处理与质量管理  
↓  
专业研究数据库  
↓  
AI 科研分析与知识关联  
↓  
开放科研协作与研究应用

各层既可以独立发展，也可以通过标准化接口连接。

### L1：DATA SOURCES — 全球数据来源层

负责建立全球生命科学数据来源体系。

主要来源包括：

1. 全球公开科研论文。
2. 全球公开科研数据库。
3. 宠物主人主动授权提供的数据。
4. 动物医院和兽医机构。
5. 第三方检测实验室。
6. 高校和科研机构。
7. 合作科研项目。
8. 公开专利和临床研究资料。
9. 公开生物医学及动物医学数据集。
10. 合法授权的研究数据和检测数据。

数据入口未来可以包括：

- VINNO 官方网站。
- VINNO PET HEALTH 产品。
- Web 数据上传平台。
- CSV / Excel / JSON / JSONL 批量导入。
- 合作机构 API。
- GitHub 开放标准与数据项目。
- 研究项目数据接口。

原则：所有数据必须保留来源信息、使用许可和授权范围。公开可访问不等于可以任意复制、再分发或商业使用。

### L2：VULS UNIVERSAL DATA STANDARD — 统一数据标准层

建设：

**VINNO Universal Life Science Data Standard（VULS）**

VULS 是整个网络的核心基础设施之一。

它不是一个数据库，而是一套跨领域生命科学数据标准。

主要解决：

- 不同机构的数据格式不同。
- 不同检测设备的指标名称不同。
- 不同国家使用的单位不同。
- 不同物种的指标定义不同。
- 同一个指标在不同检测方法下不可直接比较。
- 不同研究项目的数据记录方式不同。
- 数据来源、质量和授权信息缺失。
- 数据修订后无法追溯历史版本。

VULS 需要逐步建立：

- 数据结构与 Schema。
- 物种与研究对象定义。
- 指标词典与术语体系。
- 单位和数据类型。
- 测量方法与仪器信息。
- 观察时间与录入时间。
- 数据来源与溯源信息。
- 数据质量和审核状态。
- 数据授权与使用限制。
- 版本管理与修订记录。
- 数据集清单与版本锁定机制。

不同物种需要拥有各自适用的 Profile、指标定义、测量方法和质量规则，再通过有证据支持的映射关系实现跨物种关联，而不是简单地混合数据。

### L3：DATA PROCESSING & QUALITY — 数据处理与质量管理层

负责将不同来源的数据转换为符合 VULS 标准的结构化数据。

主要功能：

1. 数据导入。
2. 数据格式识别。
3. 字段映射。
4. 单位转换。
5. 数据标准化。
6. 数据去重。
7. 结构校验。
8. 关联关系校验。
9. 数据来源检查。
10. 数据质量评估。
11. 数据审核状态管理。
12. 数据版本与修订追踪。
13. 数据集生成和质量报告。

数据质量不能只用一个简单分数表示。

需要分别管理：

- Structural Quality：结构质量。
- Measurement Quality：测量质量。
- Provenance Quality：来源与溯源质量。
- Review Status：审核状态。
- Permission Status：授权与使用权限。
- Revision Integrity：版本和修订完整性。

其中，Validator 是数据验证工具，是这一层的基础组件之一，不等于完整的数据处理平台。

### L4：RESEARCH DATABASES — 专业研究数据库层

建立不同领域、不同物种和不同研究方向的专业数据库。

各数据库保持独立的数据模型和管理边界，但共享 VULS 标准、基础术语和关联规则。

数据库建设原则：

- 独立的数据模型。
- 独立的数据权限。
- 统一的数据标准。
- 独立的数据质量管理。
- 可追溯的数据来源。
- 独立的数据版本。
- 明确的使用许可。
- 标准化 API 与数据交换接口。
- 支持跨数据库关联。

### L5：AI RESEARCH ENGINE — 人工智能科研引擎

利用成熟 AI 模型、专业数据库、科学文献和结构化研究数据，建立生命科学领域的专业 AI 工作流。

主要方向：

- AI 论文检索与分析。
- AI 科研信息抽取。
- AI 检测报告结构化。
- AI 数据清洗与质量辅助。
- AI 科研知识图谱。
- AI 跨物种研究关联。
- AI 研究假设辅助生成。
- AI 研究设计辅助。
- AI 科研情报分析。

AI 生成的内容需要保留原始来源、证据等级和适用范围。

AI 提出的研究线索不等于经过实验验证的科学结论。

### L6：OPEN SCIENCE NETWORK — 开放科研协作网络

逐步连接全球生命科学领域的研究者、机构、实验室、开发者和合作项目。

未来包括：

- Researcher Profiles：研究人员档案。
- Institution Directory：科研机构目录。
- Laboratory Network：实验室网络。
- Research Projects：科研项目。
- Dataset Registry：数据集目录。
- Open Research：开放研究。
- Developer Community：开发者社区。
- Collaboration Hub：科研协作中心。

开放科研不代表所有数据公开。

不同数据集应根据来源许可、用户授权、科研伦理和隐私要求，确定开放、受限共享或仅内部使用的范围。

## 3.3 各数据库建设原则

每个数据库应具备：

1. 独立的数据模型。
2. 独立的数据结构和存储策略。
3. 统一的基础字段。
4. 独立的数据质量管理。
5. 独立的数据来源和授权管理。
6. 标准化的数据接口。
7. 独立的数据版本管理。
8. 与其他数据库建立可追溯的关联关系。

不建议将所有生命科学数据放在一张大表中。

例如：

宠物微生物组数据不能直接等同于人类微生物组数据。

犬类的年龄、体重、血液指标参考范围，也不能直接套用在人类身上。

跨物种研究应该通过标准化指标、研究对象、测量方法、物种映射和关联证据实现，而不是简单混合数据。

# 四、VULS — VINNO Universal Life Science Data Standard

## 4.1 统一数据标准

项目名称：

**VINNO Universal Life Science Data Standard**

缩写：

**VULS**

VULS 是 VINNO LIFE SCIENCE NETWORK 的核心数据基础设施。

目标是让不同国家、不同检测机构、不同科研项目和不同研究领域的数据能够被识别、转换、验证和关联。

VULS 本身不等于数据库，也不绑定单一编程语言。

它应该能够被 Python、R、JavaScript、Java 等不同技术体系使用。

建议独立建设：

- `vinno-universal-data-standard`
- `vinno-data-validator`

前者负责标准定义、Schema、词典、规则和示例。

后者负责提供参考验证实现。

## 4.2 数据标准的核心组成

VULS 逐步包含：

| 组成 | 说明 |
|---|---|
| Subject | 研究对象定义 |
| Study | 研究项目定义 |
| Enrollment | 研究对象与研究项目的参与关系 |
| Observation | 具体观察或测量记录 |
| Metric Dictionary | 指标词典 |
| Species Profile | 物种数据规范 |
| Method | 测量和检测方法 |
| Instrument | 仪器与设备信息 |
| Observer | 观察者或记录者 |
| Provenance | 数据来源与溯源信息 |
| Quality | 数据质量与审核状态 |
| Revision | 数据修订和版本管理 |
| Dataset Manifest | 数据集清单与版本锁定 |
| Permission | 数据授权和使用范围 |

## 4.3 纵向观察数据结构

VULS 不只是描述一条孤立的数据记录，还需要支持长期纵向观察。

目前采用的基本数据组织方式：

### Subjects

研究对象信息。

例如：

- subject_id
- species
- breed
- sex
- date_of_birth
- age_estimate
- subject_metadata

### Studies

研究项目或观察项目。

例如：

- study_id
- study_name
- study_type
- start_date
- end_date
- study_protocol

### Enrollments

研究对象与研究项目之间的参与关系。

例如：

- enrollment_id
- subject_id
- study_id
- enrolled_at
- enrollment_status

### Observations

每一次具体观察或测量。

例如：

- observation_id
- subject_id
- study_id
- observed_at
- entered_at
- metric
- value
- unit
- method
- observer
- provenance
- quality

这样可以避免每次记录都重复存储研究对象的基础信息，也能够支持长期趋势分析。

## 4.4 测量与观察上下文

一条观察记录不仅需要记录数值，还应保留测量发生的上下文。

主要包括：

- observed_at：实际观察或测量时间。
- entered_at：数据录入时间。
- method：测量方法。
- instrument：测量仪器。
- observer：观察者。
- provenance：数据来源。
- quality：数据质量与审核信息。
- scoring_system：评分体系。
- quantity_basis：数量统计口径。
- observation_period：观察周期。

例如：

体重记录需要考虑测量仪器和测量方法。

体况评分需要明确使用哪一种评分体系。

食物摄入量需要区分提供量和实际摄入量。

活动时长需要明确观察周期。

不同来源的数据即使指标名称相同，也不一定能够直接比较。

## 4.5 数据来源、质量与授权管理

数据来源、数据质量、审核状态和使用权限是不同维度，不能混为一谈。

### 数据来源分类

| 等级 | 数据来源 | 使用方式 |
|---|---|---|
| D1 | 公开科研论文、公共数据库 | 根据原始来源许可使用 |
| D2 | 用户主动上传的数据 | 根据用户授权范围使用 |
| D3 | 第三方检测机构数据 | 根据合同和用户授权使用 |
| D4 | 合作科研项目数据 | 根据研究协议和伦理要求使用 |

D1-D4 是项目内部的数据来源与治理分类，不代表数据质量等级。

### 数据质量与审核状态

例如：

- Unverified：尚未核验。
- Source Checked：来源信息已经核查。
- Reviewed：经过人工审核。
- Flagged：存在需要关注的问题。
- Excluded：不纳入当前有效数据集。

这些状态反映记录的处理和审核进度，不代表科学结论已经得到证明。

### 数据授权管理

不同数据需要明确：

- 是否允许内部使用。
- 是否允许科研使用。
- 是否允许公开展示。
- 是否允许再分发。
- 是否允许商业使用。
- 是否允许第三方共享。
- 是否存在地域或时间限制。

用户上传的数据默认保持私有，不能因为进入 VINNO 产品就自动成为公共科研数据。

## 4.6 数据版本与修订机制

科研数据必须保留历史变化记录。

对于已经提交的观察数据，原则上不应通过直接覆盖的方式修改历史记录。

应逐步建立：

- Observation ID：一次真实观察的稳定标识。
- Revision ID：某个版本的唯一标识。
- Revision Number：版本序号。
- Previous Revision ID：前一个版本。
- Revision Type：初始记录、更正、撤销等。
- Revision Reason：修改原因。
- Revision Status：当前、已替代、已撤销。

例如：

同一次体重观察最初记录为28.5 kg，后来发现录入错误，更正为28.8 kg。

应保留原始版本，并将28.8 kg作为新的修订版本。

这不是新增一次体重观察，而是对原观察记录的修订。

撤销也不应简单删除历史记录。

## 4.7 数据集清单与版本管理

不同研究数据集需要独立的版本管理。

Dataset Version 不等于 VULS Standard Version。

数据集清单应逐步包含：

- Dataset ID。
- Dataset Name。
- Dataset Version。
- VULS Version。
- Created At。
- Study IDs。
- Observation Count。
- Source Information。
- License。
- Permitted Uses。
- Publication Status。
- Revision References。
- Checksum。
- Limitations。

数据集应尽可能锁定具体的 Observation Revision ID，而不仅仅记录数据条数。

这样才能保证研究分析能够追溯到实际使用的数据版本。

## 4.8 VULS 未来扩展方向

VULS 后续可以建立：

- VULS Species Ontology：物种标准。
- VULS Biomarker Dictionary：生物标志物词典。
- VULS Clinical Observation Schema：临床观察标准。
- VULS Microbiome Schema：微生物组数据标准。
- VULS Genetics Schema：遗传数据标准。
- VULS Research Metadata：科研元数据标准。
- VULS Data Quality Framework：数据质量体系。
- VULS Dataset Manifest：数据集版本规范。
- VULS Revision Framework：数据修订规范。

当前优先完善基础数据结构、犬类纵向观察、数据验证、来源溯源、质量管理和版本管理。

不以一次性建立完整生命科学标准为目标，而是通过实际研究场景逐步扩展。

# 五、VINNO PET HEALTH 产品架构

## 5.1 产品定位

VINNO PET HEALTH 是整个网络最重要的早期商业应用和数据入口之一。

它既是宠物主人管理宠物健康的工具，也是未来宠物健康寿命研究的数据来源之一。

产品不应仅仅做成一个商城。

核心定位：

**宠物数字健康档案 + 检测服务 + AI 报告辅助分析 + 长期健康管理。**

## 5.2 用户端六大模块

### 模块一：宠物数字档案

功能：

- 创建宠物档案。
- 宠物名称。
- 猫/狗。
- 品种。
- 出生日期。
- 性别。
- 绝育情况。
- 体重。
- 生活环境。
- 饮食情况。
- 既往病史。

每只宠物建立唯一 ID。

例如：

`PET-2026-000001`

年龄信息需要区分准确出生日期、估计年龄和未知年龄，不应将估计年龄伪装成准确出生日期。

### 模块二：健康记录

记录：

- 体重。
- 饮食。
- 排便。
- 活动。
- 睡眠。
- 疫苗。
- 驱虫。
- 体检。
- 疾病和健康事件。
- 用药记录。

首版不宜设置过多复杂项目。

先让用户能够低成本、持续地记录。

### 模块三：AI 检测报告分析

用户可以上传：

- 血常规。
- 生化检测。
- 尿液检测。
- 基因检测。
- 微生物组检测。
- 综合体检报告。

AI 工作流程：

上传报告  
↓  
OCR / 多模态识别  
↓  
识别检测项目  
↓  
提取数值和单位  
↓  
提取实验室参考范围  
↓  
用户确认  
↓  
生成结构化数据  
↓  
保存到宠物档案  
↓  
形成长期趋势

报告分析必须保留原始文件。

AI 不得自行编造检测值、参考区间或诊断结论。

对无法识别的项目，应明确标记为待确认。

AI 报告辅助不能替代兽医诊断。

### 模块四：宠物检测服务中心

提供：

1. 宠物基因检测。
2. 宠物肠道微生态检测。
3. 血液检测。
4. 生化检测。
5. 临床病原检测。
6. 其他专业检测服务。

合作模式：

用户下单  
↓  
平台生成订单  
↓  
第三方机构提供采样服务或采样指导  
↓  
样本送检  
↓  
实验室完成检测  
↓  
报告回传  
↓  
AI 结构化  
↓  
用户查看报告

VINNO 前期不需要建设自己的实验室。

应优先与成熟第三方实验室合作，并逐个检测项目核实资质、方法和质量控制能力。

### 模块五：健康寿命管理

核心功能：

- 体重趋势。
- 体况记录。
- 活动趋势。
- 饮食变化。
- 检测指标趋势。
- 健康事件时间轴。
- 定期体检提醒。
- 健康档案总结。

初期不建议直接生成所谓的“宠物生物年龄”。

除非有经过验证的算法、训练数据和适用范围，否则容易造成虚假精确。

健康寿命管理应以长期、可追溯的指标变化为基础。

### 模块六：科研参与中心

让宠物主人可以自愿参加研究项目。

例如：

- 老年犬健康观察项目。
- 犬类体重与健康研究。
- 犬类微生态长期观察。
- 宠物健康寿命纵向研究。

每个研究项目必须清楚说明：

- 研究目的。
- 研究对象。
- 收集的数据。
- 数据用途。
- 数据保留期限。
- 是否会公开汇总数据。
- 是否会与第三方共享。
- 用户退出机制。
- 是否涉及生物样本。

研究项目需要相应的伦理审查、授权和专业人员参与。

商业产品中积累的用户数据，不会自动转变为科研数据。科研使用必须具有独立、明确的授权和治理依据。

# 七、VINNO SCIENCE ENGINE — AI 科研引擎

## 7.1 产品定位

VINNO SCIENCE ENGINE 是整个开放科研网络的智能分析系统。

目标不是训练一个新的大模型。

而是利用现有成熟 AI 模型、专业数据库和科学数据标准，建立生命健康领域的专业 AI 工作流。

它的核心价值不是简单回答问题，而是帮助研究人员完成：

- 科研信息检索。
- 文献结构化。
- 数据整理。
- 证据关联。
- 科研知识发现。
- 研究假设辅助。
- 跨物种研究分析。

## 7.2 四大核心引擎

### 1. AI Literature Intelligence

科研文献智能引擎。

功能：

- 全球论文检索。
- 论文摘要。
- 研究对象识别。
- 研究方法提取。
- 样本量提取。
- 研究结果提取。
- 研究局限提取。
- 证据等级整理。
- DOI 和原始来源记录。
- 论文之间的关联分析。

目标是建立可检索、可追溯、可持续更新的科研文献数据资产。

### 2. AI Knowledge Graph

科研知识图谱引擎。

逐步建立以下核心实体：

- Species
- Breed
- Gene
- Protein
- Biomarker
- Disease
- Pathway
- Ingredient
- Intervention
- Study
- Publication
- Clinical Trial
- Research Institution

通过实体和关系连接不同数据库。

例如：

某种成分  
→ 相关分子通路  
→ 某种生物标志物  
→ 某个物种的研究  
→ 某篇科研论文  
→ 相关临床研究

所有关系应保留证据来源、研究类型、物种适用范围和证据强度。

### 3. AI Hypothesis & Research Assistant

科研假设与研究辅助引擎。

功能：

- 文献综述。
- 研究资料整理。
- 数据清洗。
- 统计分析辅助。
- 研究设计辅助。
- 研究空白识别。
- 研究假设生成。
- 论文结构辅助。
- 专利技术分析。
- 科研项目情报。

AI 可以提出研究假设和实验设计建议，但不能把推测写成已经验证的科学结论。

### 4. AI Cross-species Intelligence

跨物种研究引擎。

例如：

犬类衰老研究与人类衰老研究之间的关联。

可以建立：

- 基因关联。
- 蛋白质关联。
- 代谢通路关联。
- 微生物组关联。
- 生物标志物关联。
- 研究证据关联。

需要特别注意：

不同物种的生理特征、寿命、代谢、疾病谱和检测方法存在差异。

AI 只能在保留物种信息、研究方法和证据边界的基础上提出关联与研究线索。

不能因为两个物种存在某种相似指标，就认定其机制、治疗效果或临床意义相同。

## 7.3 AI 引擎的建设阶段

| 阶段 | 能力 | 主要目标 |
|---|---|---|
| AI 1.0 | 文献检索与结构化 | 建立科研文献数据资产 |
| AI 2.0 | 证据关联与知识图谱 | 建立科研知识网络 |
| AI 3.0 | 研究假设与研究辅助 | 提升科研信息分析效率 |
| AI 4.0 | 跨物种研究与数据分析 | 支持比较衰老研究 |

AI 科研引擎必须建立在真实、可追溯的数据资产之上。

不建议在基础数据标准和专业数据库尚未成熟时，优先投入资源建设复杂的 AI 系统。

# 八、数据治理、科研伦理与开放科学原则

## 8.1 数据治理原则

VINNO 遵循以下原则：

1. Data Provenance：所有数据尽可能保留来源。
2. Data Quality：建立可解释的数据质量规则。
3. Data Integrity：保留原始记录和修订历史。
4. Data Permission：明确数据使用权限。
5. Data Privacy：保护用户和研究对象隐私。
6. Reproducibility：研究数据和分析过程尽可能可追溯。
7. Transparency：明确数据局限和研究边界。
8. Interoperability：支持不同系统之间的数据交换。

## 8.2 商业数据与科研数据的边界

VINNO 的商业业务和科研体系可以共享基础技术设施，但不能默认共享所有数据。

例如：

用户在 VINNO PET HEALTH 中创建的宠物档案，首先属于用户授权范围内的健康管理数据。

如果未来希望将其用于科研，需要明确研究目的、授权范围、数据处理方式和退出机制。

第三方检测机构的数据，也必须根据合同、用户授权和相关许可确定用途。

## 8.3 人类健康与遗传数据

未来涉及人类健康数据、遗传信息和跨境科研合作时，应根据适用法律法规建立相应的合规体系。

包括但不限于：

- 个人信息保护。
- 敏感个人信息处理。
- 人类遗传资源相关规定。
- 科研伦理审查。
- 数据跨境传输要求。
- 第三方数据使用许可。

人类健康寿命研究早期优先使用合法公开论文和公共数据集。

不在缺乏合规能力、专业合作和伦理条件的情况下，提前收集或处理个人健康和遗传数据。

## 8.4 科研伦理与证据原则

VINNO 不以商业宣传替代科学证据。

所有研究应尽可能明确：

- 研究对象。
- 研究设计。
- 样本量。
- 观察时间。
- 检测方法。
- 数据来源。
- 统计方法。
- 研究局限。
- 证据等级。

宠物健康寿命研究需要长期观察。

不能通过短期检测或单一指标变化，直接宣称某项产品能够延长寿命。

宠物研究也不能替代人体安全性和有效性研究。

# 九、项目长期发展路线

VINNO 的发展不是一次性建设完整的生命科学网络，而是通过具体应用场景逐步建立基础设施、数据资产和科研合作能力。

## 第一阶段：PET HEALTH — 宠物健康寿命

以宠物健康寿命为切入点。

主要建设：

- 宠物健康产品和服务。
- 宠物数字健康档案。
- 检测服务体系。
- VULS 数据标准。
- 数据验证工具。
- 宠物健康数据库。
- 宠物长期观察项目。
- 科研文献目录。

核心目标：

建立真实的用户需求、数据入口、服务能力和初步研究数据资产。

## 第二阶段：ANIMAL LONGEVITY — 动物健康与寿命研究

从犬猫扩展到其他动物。

研究方向：

- 不同动物寿命差异。
- 长寿动物。
- 衰老相关基因。
- 代谢和微生物组。
- 动物健康寿命指标。
- 不同物种的衰老特征。

核心目标：

建立更广泛的动物寿命与健康数据体系。

## 第三阶段：COMPARATIVE AGING — 比较衰老研究

建立跨物种研究网络。

通过基因、蛋白质、代谢通路和生物标志物建立关联。

寻找：

- 不同物种共有的衰老机制。
- 长寿物种的特殊生物学特征。
- 可能具有保护作用的机制。
- 值得进一步验证的研究假设。

核心目标：

从单一物种研究逐步进入比较生物学和跨物种衰老研究。

## 第四阶段：HUMAN HEALTHSPAN — 人类健康寿命研究

逐步进入人类健康寿命研究。

初期以：

# 十三、项目核心原则

VINNO 的长期发展建立在以下原则之上：

**1. Data First — 数据优先**

先建立真实、结构化、可追溯的数据资产，再建设复杂 AI 系统。

**2. Standard First — 标准优先**

通过统一标准实现不同数据来源和研究系统之间的互操作。

**3. Evidence First — 证据优先**

所有研究结论必须保留证据来源、研究方法和适用边界。

**4. Open Science — 开放科学**

推动标准、工具、研究方法和合规数据的开放协作。

**5. Longitudinal Research — 长期观察**

健康寿命研究需要长期数据积累，不能用短期指标替代长期结论。

**6. Cross-species Research — 跨物种研究**

尊重不同物种的生物学差异，通过可解释的关联和证据开展比较研究。

**7. Responsible AI — 负责任的人工智能**

AI 用于辅助科研和数据分析，不替代专业诊断、伦理审查和实验验证。

**8. Independent Research Governance — 独立科研治理**

商业数据和科研数据应有清晰的授权、管理和使用边界。

VINNO LIFE SCIENCE NETWORK 是一个持续建设中的生命科学数据基础设施与开放科研网络项目。

本仓库描述的是总体架构、产品开发蓝图、技术方向和阶段性建设计划。

文档中提到的未来数据库、AI 科研系统、研究网络、合作机构和研究项目，除明确标注已实现或已建立的内容外，均属于规划、研究方向或潜在合作方向。

项目中的示例数据均为虚构数据，不能作为真实临床数据或科研结论使用。

数据通过 Validator 验证，不代表数据测量本身一定准确，也不代表相关科学结论已经得到验证。

VINNO 不提供替代兽医或医生的诊断服务，也不通过单次检测或未经验证的算法承诺延长宠物或人类寿命。

涉及真实研究、人体数据、生物样本和跨境数据合作时，应根据适用法律法规、数据授权和科研伦理要求开展。

# XV. 项目最终愿景

VINNO 希望从宠物健康寿命这一具体领域出发，逐步建立连接动物健康、衰老机制、比较生物学和人类健康寿命研究的数据基础设施。

从真实的宠物健康记录开始。

建立统一的数据标准。

积累长期、可追溯的研究数据。

建立专业数据库和科研知识网络。

利用人工智能提高科研信息处理和研究分析效率。

**先建立真实的数据和服务能力，再建立科研影响力；先完成宠物健康领域的商业与数据闭环，再逐步扩展到全球生命健康科学。**

## 本地测试说明

以下命令适用于已获取对应标准仓库和验证器仓库的开发环境。

```bash
cd vinno-data-validator

python3 -m venv .venv

source .venv/bin/activate

pip install -e ".[dev]"

pytest
```

检查一套纵向示例：

```bash
vuls validate-dataset \
  ../vinno-universal-data-standard/examples/datasets/synthetic-weight-follow-up \
  --schemas ../vinno-universal-data-standard/schemas/0.2 \
  --dictionaries ../vinno-universal-data-standard/dictionaries
```

校验一条单次观察：

```bash
vuls validate \
  ../vinno-universal-data-standard/examples/valid/canine-body-weight.json \
  --schema ../vinno-universal-data-standard/schemas/observation-record.schema.json \
  --dictionaries ../vinno-universal-data-standard/dictionaries
```

具体目录、命令和参数以当前仓库实际版本为准。
