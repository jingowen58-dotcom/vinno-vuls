# 第一部分：项目总体定位

## 1.1 项目愿景

建设一个以开放数据、科学研究、人工智能和全球协作为基础的生命健康研究网络。

从宠物健康寿命开始，逐步连接动物医学、遗传学、微生物组学、生物标志物、衰老机制、健康寿命研究以及人类健康科学。

通过标准化数据体系、独立专业数据库、AI 科研工具和开放协作机制，让分散在全球科研论文、检测机构、动物医院、实验室、宠物主人和科研人员手中的数据，能够在合规授权的前提下被整理、理解、分析和利用。

## 1.2 核心使命

1. 建立全球生命健康领域的开放数据基础设施。
2. 建立覆盖宠物、动物和人类健康寿命的专业数据库。
3. 建立统一的数据标准和跨物种数据关联体系。
4. 利用 AI 降低科研信息获取、数据整理和分析的门槛。
5. 连接全球科研机构、检测实验室、兽医、研究人员和用户。
6. 通过真实、可验证的研究，推动健康寿命科学发展。

## 1.3 项目定位

VINNO LIFE SCIENCE NETWORK 不是单一的宠物产品品牌，也不是传统检测实验室。

它是一个由五部分组成的开放科学网络：

- 数据基础设施：收集、管理和标准化生命健康数据。
- 专业数据库：形成不同物种、领域和研究方向的数据资产。
- AI 科研引擎：帮助用户和研究人员理解数据、分析文献、发现研究线索。
- 开放科研社区：连接科研人员、检测机构、动物医院和用户。
- 商业应用体系：通过宠物健康管理、检测服务、科研工具和产品实现商业化。

# 第二部分：全球生命健康开放科研网络总体架构

## 2.1 五层总体架构

### 第一层：DATA COLLECTION
全球数据采集层。

数据来源：

1. 全球公开科研论文。
2. 全球公开科研数据库。
3. 宠物主人主动上传的数据。
4. 动物医院和兽医机构。
5. 第三方检测实验室。
6. 高校和科研机构。
7. 合作研究项目。
8. 公开专利和临床研究资料。

数据入口：

- VINNO 官网。
- VINNO PET HEALTH 小程序。
- Web 数据上传平台。
- CSV/Excel 批量导入。
- 合作机构 API。
- GitHub 开放数据项目。

### 第二层：DATA STANDARD
统一数据标准层。

建设：

VINNO Universal Life Science Data Standard，简称 VULS。

它是整个网络最重要的基础设施之一。

负责解决：

- 不同机构数据格式不同。
- 不同检测设备指标名称不同。
- 不同国家使用的单位不同。
- 不同物种的指标定义不同。
- 同一个指标在不同检测方法下不可直接比较。
- 不同研究项目的数据质量和可信度不同。

VULS 不只是规定字段名称，还要包含：

- 指标定义。
- 数据类型。
- 单位。
- 检测方法。
- 数据来源。
- 质量等级。
- 参考范围来源。
- 授权状态。
- 版本信息。
- 数据使用限制。

### 第三层：RESEARCH DATABASES
专业数据库层。

每一个数据库独立建设、独立维护。

但共享统一的数据标准和身份体系。

### 第四层：AI INTELLIGENCE
人工智能分析层。

包括：

- AI 论文分析。
- AI 检测报告识别。
- AI 健康档案管理。
- AI 数据清洗。
- AI 研究辅助。
- AI 跨物种研究关联。
- AI 科研知识图谱。

### 第五层：OPEN SCIENCE NETWORK
开放科研协作层。

连接：

- 全球科研人员。
- 大学和研究机构。
- 动物医院。
- 检测实验室。
- 宠物主人。
- 生物技术公司。
- 开源开发者。

最终形成：

数据采集 → 数据标准化 → 专业数据库 → AI 分析 → 科研合作 → 数据和知识积累 → 新的研究和应用。

| DB02 | VINNO Pet Genetics Database | 宠物遗传数据库 | 遗传变异、品种、遗传风险 |
| DB03 | VINNO Pet Microbiome Database | 宠物微生物组数据库 | 肠道菌群、微生物组成 |
| DB04 | VINNO Pet Biomarker Database | 宠物生物标志物数据库 | 血液、生化、炎症及其他指标 |
| DB05 | VINNO Animal Longevity Database | 动物寿命数据库 | 物种、品种、寿命、死亡原因 |
| DB06 | VINNO Comparative Aging Database | 跨物种衰老数据库 | 衰老机制、基因、通路 |
| DB07 | VINNO Human Healthspan Research Database | 人类健康寿命研究数据库 | 公开研究、健康寿命指标 |
| DB08 | VINNO Human Biomarker Database | 人类生物标志物数据库 | 公开文献中的生物标志物 |

| DB11 | VINNO Longevity Clinical Trial Database | 健康寿命临床研究数据库 | 试验、研究设计、研究结果 |
| DB12 | VINNO Patent & Innovation Database | 健康寿命专利创新数据库 | 专利、技术、创新项目 |

## 3.2 每个数据库的建设原则

每个数据库都应具备：

1. 独立的数据模型。
2. 独立的数据库表和数据权限。
3. 统一的基础字段。
4. 独立的数据质量管理。
5. 独立的数据来源和授权管理。
6. 独立的 API。
7. 独立的数据版本管理。
8. 与其他数据库建立关联关系。

不建议把12个数据库全部放在一张大表中。

例如：

宠物微生物组数据不能直接等同于人类微生物组数据。

犬类的年龄、体重、血液指标参考范围，也不能直接套用在人类身上。

跨物种研究应该通过标准化指标、研究对象和关联机制实现，而不是简单混合数据。

## 3.3 数据库优先级

虽然长期规划12个数据库，但前期不应该同时开发。

| 优先级 | 数据库 | 建设方式 | 主要目的 |

| P0 | Pet Healthspan | 自建 | 建立真实用户数据入口 |
| P0 | Aging Research | 整理公开数据 | 建立科研内容资产 |
| P0 | Longevity Ingredient | 整理公开数据 | 支持产品科学评估 |
| P1 | Pet Biomarker | 自建标准+合作接入 | 检测报告结构化 |
| P1 | Pet Microbiome | 合作接入 | 连接微生态检测 |
| P1 | Animal Longevity | 整理公开数据 | 研究动物寿命 |
| P2 | Pet Genetics | 合作/公开数据 | 遗传研究 |
| P2 | Clinical Trials | 整理公开数据 | 追踪科研进展 |
| P2 | Patent Intelligence | 整理公开数据 | 技术和专利分析 |
| P3 | Comparative Aging | 自建知识关联 | 跨物种研究 |
| P3 | Human Healthspan | 公开数据起步 | 人类健康寿命研究 |
| P3 | Human Biomarker | 公开文献起步 | 人类生物标志物研究 |

# 第四部分：VINNO Universal Life Science Data Standard

## 4.1 统一数据标准

项目名称：

VINNO Universal Life Science Data Standard

缩写：

VULS

建议独立建立 GitHub 仓库：

vinno-universal-data-standard

目标：

让不同国家、不同检测机构、不同科研项目的数据能够被识别、转换、验证和关联。

## 4.2 基础数据结构

所有数据至少应包含以下信息：

| 字段 | 说明 |
|---|---|
| record_id | 数据记录唯一编号 |
| subject_id | 研究对象编号 |
| species | 物种 |
| breed | 品种 |
| age | 年龄 |
| sex | 性别 |
| observation_type | 观察指标类型 |
| observation_value | 指标数值 |
| observation_unit | 数值单位 |
| recorded_at | 记录时间 |
| source | 数据来源 |
| method | 检测方法 |
| laboratory | 检测机构 |
| quality_status | 数据质量状态 |
| verification_status | 验证状态 |
| authorization_status | 授权状态 |
| created_at | 创建时间 |
| schema_version | 数据标准版本 |

## 4.3 数据示例

```json
{
  "record_id": "REC-000001",
  "subject_id": "PET-000001",
  "species": "Canis lupus familiaris",
  "breed": "Golden Retriever",
  "age": {
    "value": 5,
    "unit": "year"
  },
  "sex": "male",
  "observation": {
    "type": "body_weight",
    "value": 28.5,
    "unit": "kg",
    "recorded_at": "2026-10-30"
  },
  "source": {
    "type": "owner_reported",
    "verification_status": "unverified"
  },
  "quality_status": "pending",
  "authorization_status": "private",
  "schema_version": "VULS-0.1"
}
```

## 4.4 数据来源分级

| 等级 | 数据来源 | 使用方式 |
|---|---|---|
| D1 | 公开科研论文、公共数据库 | 按来源许可使用 |
| D2 | 用户主动上传的数据 | 按授权范围使用 |
| D3 | 第三方检测机构数据 | 按合同和用户授权使用 |
| D4 | 合作科研项目数据 | 按研究协议使用 |

同时建立数据可信度等级：

- Verified：来源和关键字段已经核验。
- Partially Verified：部分字段经过核验。
- Unverified：尚未核验。
- Rejected：不符合数据要求。

数据来源等级与数据可信度等级是两个不同维度，不能混为一谈。

## 4.5 指标标准化

例如体重：

```json
{
  "metric_id": "PET.BODY_WEIGHT",
  "name": "Body Weight",
  "species": "Canis lupus familiaris",
  "data_type": "numeric",
  "unit": "kg",
  "allowed_methods": [
    "digital_scale",
    "veterinary_scale"
  ]
}
```

例如血液指标：

```json
{
  "metric_id": "PET.BLOOD.ALT",
  "name": "Alanine Aminotransferase",
  "species": "Canis lupus familiaris",
  "data_type": "numeric",
  "unit": "U/L",
  "method_required": true,
  "laboratory_reference_required": true
}
```

重要原则：

血液指标必须保留检测方法、仪器、实验室和参考范围来源。

不能仅凭数值相同就认定不同实验室的数据可以直接比较。

## 4.6 VULS 未来扩展

VULS 后续可以建立：

- VULS Species Ontology：物种标准。
- VULS Biomarker Dictionary：生物标志物词典。
- VULS Clinical Observation Schema：临床观察标准。
- VULS Microbiome Schema：微生物组数据标准。
- VULS Genetics Schema：遗传数据标准。
- VULS Research Metadata：科研元数据标准。
- VULS Data Quality Framework：数据质量体系。

V1.0 只需要完成基础字段、宠物健康记录和检测报告结构。

# 第五部分：VINNO PET HEALTH 产品架构

## 5.1 产品定位

VINNO PET HEALTH 是整个网络最重要的前端产品。

它既是宠物主人管理宠物健康的工具，也是未来宠物健康寿命数据库的数据入口。

不应仅仅做成一个商城。

产品定位：

宠物数字健康档案 + 检测服务 + AI报告分析 + 长期健康管理。

## 5.2 用户端六大模块

### 模块一：宠物数字档案

功能：

- 创建宠物档案。
- 宠物名称。
- 猫/狗。
- 品种。
- 出生日期。
- 性别。
- 绝育情况。
- 体重。
- 生活环境。
- 饮食情况。
- 既往病史。

每只宠物建立唯一 ID。

例如：

PET-2026-000001

### 模块二：健康记录

记录：

- 体重。
- 饮食。
- 排便。
- 活动。
- 睡眠。
- 疫苗。
- 驱虫。
- 体检。
- 疾病和健康事件。
- 用药记录。

首版不宜设置过多复杂项目。

先让用户能够低成本、持续地记录。

### 模块三：AI 检测报告分析

用户可以上传：

- 血常规。
- 生化检测。
- 尿液检测。
- 基因检测。
- 微生物组检测。
- 综合体检报告。

AI 工作流程：

上传报告  
↓  
OCR/多模态识别  
↓  
识别检测项目  
↓  
提取数值和单位  
↓  
提取实验室参考范围  
↓  
用户确认  
↓  
生成结构化数据  
↓  
保存到宠物档案  
↓  
形成长期趋势。

报告分析必须保留原始文件。

AI 不得自行编造检测值、参考区间或诊断结论。

对无法识别的项目，应明确标记为待确认。

### 模块四：宠物检测服务中心

提供：

1. 宠物基因检测。
2. 宠物肠道微生态检测。
3. 血液检测。
4. 生化检测。
5. 临床病原检测。
6. 其他专业检测服务。

合作模式：

用户下单  
↓  
平台生成订单  
↓  
第三方机构提供采样服务或采样指导  
↓  
样本送检  
↓  
实验室完成检测  
↓  
报告回传  
↓  
AI 结构化  
↓  
用户查看报告。

VINNO 前期不需要建设自己的实验室。

应优先与成熟第三方实验室合作。

### 模块五：健康寿命管理

核心功能：

- 体重趋势。
- 体况记录。
- 活动趋势。
- 饮食变化。
- 检测指标趋势。
- 健康事件时间轴。
- 定期体检提醒。
- 健康档案总结。

初期不建议直接生成所谓的“宠物生物年龄”。

除非有经过验证的算法、训练数据和适用范围，否则容易造成虚假精确。

### 模块六：科研参与中心

让宠物主人可以自愿参加研究项目。

例如：

- 老年犬健康观察项目。
- 犬类体重与健康研究。
- 犬类微生态长期观察。
- 宠物健康寿命纵向研究。

每个研究项目必须清楚说明：

- 研究目的。
- 研究对象。
- 收集的数据。
- 数据用途。
- 数据保留期限。
- 是否会公开汇总数据。
- 是否会与第三方共享。
- 用户退出机制。
- 是否涉及生物样本。

研究项目需要相应的伦理审查、授权和专业人员参与。

# 第六部分：全球宠物检测机构合作体系

## 6.1 合作模式

VINNO 不需要一开始自己做检测。

更合理的方式是：

VINNO 负责用户入口、订单、数据标准、AI分析和健康管理。

检测机构负责采样、实验室检测和专业报告。

双方通过 API、文件接口或人工后台实现连接。

## 6.2 全球主要竞品和参考机构

| 企业/机构 | 主要领域 | 值得学习的方向 |
|---|---|---|
| Embark | 宠物基因检测 | 消费级基因检测产品和数据服务 |
| Wisdom Panel | 宠物基因检测 | 遗传和健康筛查 |
| AnimalBiome | 宠物微生态 | 检测、报告、产品和复测闭环 |
| IDEXX | 动物临床检测 | 检测数据和临床工作流 |
| Zoetis | 动物健康 | 诊断和动物健康产品体系 |
| Antech | 动物诊断服务 | 第三方实验室网络 |
| SignalPET | AI影像分析 | AI辅助兽医诊断 |
| Vetology AI | AI影像分析 | 临床工作流和影像辅助 |

这些企业是市场研究和产品设计参考对象，不代表已经与 VINNO 建立合作。

## 6.3 中国候选合作机构

| 机构 | 可重点了解的方向 |
|---|---|
| 中农董军实验室 | 病理、PCR、微生物、基因等 |
| 兽丘参考实验室 | 病理、分子诊断、微生物、遗传检测 |
| 中国农业大学教学动物医院 | 动物临床检测和教学科研 |
| 拓瑞检测 | 临床检测、遗传、免疫、微生物 |
| 中科基因相关检测网络 | 动物检测及数据服务 |

上述为潜在洽谈对象，具体项目能力、资质、检测方法、服务区域和合作条件必须逐项核实。

## 6.4 检测机构准入标准

每家合作机构建立档案：

1. 公司及机构主体信息。
2. 实验室地址。
3. 经营和检测资质。
4. 具体检测项目。
5. 检测方法。
6. 检测设备。
7. 质量控制流程。
8. 是否参加能力验证。
9. 报告样本。
10. 检测周期。
11. 价格。
12. 复测政策。
13. 样本运输要求。
14. 数据接口。
15. 数据授权条款。
16. 投诉和责任机制。

特别注意：

# 第七部分：VINNO SCIENCE ENGINE——AI 科研引擎

## 7.1 产品定位

VINNO SCIENCE ENGINE 是整个开放科研网络的智能分析系统。

目标不是训练一个新的大模型。

而是利用现有成熟 AI 模型、专业数据库和科学数据标准，建立生命健康领域的专业 AI 工作流。

## 7.2 五大 AI 引擎

### 1. AI Report Engine

检测报告识别引擎。

功能：

- OCR。
- PDF解析。
- 检测项目识别。
- 数值提取。
- 单位识别。
- 参考范围提取。
- 异常标记。
- 数据结构化。
- 报告归档。

优先级：最高。

### 2. AI Research Engine

科研文献引擎。

功能：

- 全球论文检索。
- 论文摘要。
- 研究对象识别。
- 研究方法提取。
- 样本量提取。
- 研究结果提取。
- 研究局限提取。
- 证据等级整理。
- DOI和原始来源记录。

### 3. AI Health Record Engine

健康档案引擎。

功能：

- 历史数据整理。
- 指标变化趋势。
- 健康事件时间轴。
- 检测报告关联。
- 数据缺失提示。
- 定期记录提醒。

### 4. AI Cross-species Engine

跨物种研究引擎。

例如：

犬类衰老研究与人类衰老研究之间的关联。

可以建立：

- 基因关联。
- 蛋白质关联。
- 代谢通路关联。
- 微生物组关联。
- 生物标志物关联。
- 研究证据关联。

但 AI 只能提出研究线索和假设。

不能因为两个物种存在某种相似指标，就认定其机制、治疗效果或临床意义相同。

### 5. AI Research Assistant

科研辅助引擎。

功能：

- 文献综述。
- 研究资料整理。
- 数据清洗。
- 统计分析辅助。
- 研究设计辅助。
- 论文结构辅助。
- 专利技术分析。
- 科研项目情报。

研究结果必须保留可追溯来源。

# 第八部分：项目长期发展路线

## 第一阶段：PET HEALTH

以宠物健康寿命为切入点。

形成：

- 宠物用户。
- 宠物健康档案。
- 检测服务。
- 数据标准。
- 宠物健康数据库。
- 宠物产品。

## 第二阶段：ANIMAL LONGEVITY

从犬猫扩展到其他动物。

研究：

- 不同动物寿命差异。
- 长寿动物。
- 衰老相关基因。
- 代谢和微生物组。
- 动物健康寿命指标。

## 第三阶段：COMPARATIVE AGING

建立跨物种研究网络。

通过基因、蛋白质、代谢通路和生物标志物建立关联。

寻找：

- 不同物种共有的衰老机制。
- 长寿物种的特殊生物学特征。
- 可能具有保护作用的机制。
- 值得进一步验证的研究假设。

## 第四阶段：HUMAN HEALTHSPAN

逐步进入人类健康寿命研究。

初期以公开论文、公共数据库和公开研究成果为主。

后续在具备合规能力、科研合作和伦理条件后，再考虑采集人体数据或开展研究。

## 第五阶段：GLOBAL LIFE SCIENCE NETWORK

最终形成：

- 全球科研数据库。
- 跨物种研究网络。
- 开放数据标准。
- AI科研工具。
- 全球研究者社区。
- 科研机构合作网络。
- 商业化健康应用。

---

VINNO 的最终目标，是成为一个连接宠物健康、动物衰老和人类健康寿命研究的开放科学网络。

但必须坚持一个原则：

**先建立真实的数据和服务能力，再建立科研影响力；先完成宠物健康领域的商业闭环，再逐步扩展到全球生命健康科学。**



维诺要做的，是让高龄宠物的养护有据可查：先看清这只动物现在的状态，再用可核对的营养方案去照顾它，而不是用一次检测或一句延寿承诺代替兽医。

这个仓库目前只放数据标准，不放商城，也不放科研门户。VULS 用来描述一次观察从哪里来、如何测量、能否使用、后来有没有被更正。它不诊断疾病，不预测还能活多久，也不把犬、猫和人的同名指标当成可以直接比较的东西。

示例全部是虚构数据。这套草案还没有经过兽医审核。`reviewed` 只表示有人看过记录，不表示测量一定准确，更不表示研究结论成立。

## 现在已经有的

- 家犬的单次观察：体重、体况、进食量、活动时长、粪便性状。
- 同一只狗在一个研究里的多次观察，以及参加关系。
- 测量时间和录入时间分开；方法、设备、评估者和来源分开。
- 不合格记录会被拒绝，不完整的记录可以留下并标成警告或需要人工查看。
- 同一次观察的更正写成新版本，旧数值保留，撤销也不删除文件。
- 数据集清单锁定具体文件和版本。数据集版本和标准版本分开计算。

## 接下来做什么

先把质量报告按结构、测量、来源、审核、授权和版本链分开写清楚，不打一个总分。然后用一份许可允许再分发的外部小数据，试验这些字段能不能装下别人的记录，并写明对不上的地方。

文献目录、宠物健康寿命数据库和临床试验索引，要等这条链路稳定后再做。AI 问答和开放协作门户更晚。用户在产品里留下的档案不会自动变成可以公开的研究数据。

## 仓库里有什么

- `vinno-universal-data-standard`：字段、规则和虚构示例。
- `vinno-data-validator`：检查记录、修订链和数据集清单的参考实现。标准本身不依赖某一种编程语言。

```bash
cd vinno-data-validator
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest
```

检查一套纵向示例：

```bash
vuls validate-dataset \
  ../vinno-universal-data-standard/examples/datasets/synthetic-weight-follow-up \
  --schemas ../vinno-universal-data-standard/schemas/0.2 \
  --dictionaries ../vinno-universal-data-standard/dictionaries
```

校验一条单次观察：

```bash
vuls validate \

  --schema ../vinno-universal-data-standard/schemas/observation-record.schema.json \
  --dictionaries ../vinno-universal-data-standard/dictionaries
```
